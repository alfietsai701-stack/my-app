## 四、系統修正內容

**① 前一日提醒恢復運作**
`proxy.ts` 白名單加入 `/api/cron`。授權改由 `/api/cron/reminders` 內既有的 `CRON_SECRET` 檢查負責，未帶正確金鑰仍會回 401。

**② LINE 身分改為後端驗證**
- 新增 `lib/line-auth.ts`：向 LINE（`oauth2/v2.1/verify`）驗證 LIFF 的 ID token，只有驗證成功才取得 userId。channel ID 由 `NEXT_PUBLIC_LIFF_ID` 前綴推得，可用 `LIFF_CHANNEL_ID` 覆寫。
- 預約頁改送 `liff.getIDToken()`，不再送 userId。
- `/api/book/customer` 改為 POST 並驗證 token，只能查到本人綁定的資料。
- `/api/book` 綁定規則：新顧客直接綁定；既有顧客只有「尚未綁定 LINE 且姓名相符」才綁定，已綁定其他 LINE 時絕不覆寫，同一個 LINE 也不會被綁到兩位顧客。Email 只在原本空白、或請求者就是已綁定本人時才更新。
- 預約確認的 LINE 推播只發給驗證過的本人。

**③ Email 跳脫與預約限流**
- `lib/email.ts`：姓名、服務名稱、備註、店名放進 HTML 前一律跳脫；備註換行轉為 `<br/>`。
- 新增 `lib/rate-limit.ts`，`/api/book` 限制同一來源 10 分鐘 10 次、同一手機 1 小時 5 次；`/api/book/customer` 同一來源 10 分鐘 30 次。
- 欄位驗證：姓名 ≤ 50 字、備註 ≤ 500 字、Email 格式與長度檢查。

## 六、部署檢查清單

1. **LIFF 設定**：LINE Developers → LIFF app → Scopes 勾選 **`openid`**（否則拿不到 ID token，預約仍可完成，但不會綁定 LINE、不會帶入老客資料）。
2. **環境變數**：確認 Vercel 已設定 `CRON_SECRET`；若 LIFF 所屬 channel 與 LIFF ID 前綴不同，另設 `LIFF_CHANNEL_ID`。
3. **預設密碼**：確認三個管理員帳號的密碼都已不是 seed 預設值。
4. **提醒測試**：部署後於 Vercel → Cron Jobs 手動觸發一次 `/api/cron/reminders`，應回傳 `{ ok: true, candidates, sent }`。
5. **LINE 綁定測試**：用 LINE 開預約頁，第二次預約應自動帶入資料；用一般瀏覽器開，預約仍可正常完成。

> 本次無資料庫結構變更，不需執行 `prisma db push`。
